# プレイヤー統計

`/players/statistics` はDiscordログイン必須の統計ページ。
年齢層・ランク・居住国・入力デバイスの分布と、キャラ別対戦数・勝率を同じ条件で集計する。
例えば年齢層で「20代」を選ぶと、20代の人々のランク分布を確認できる。
グラフのラベル・キャラ名も絞り込みボタン。条件はURLに保存し、戻る・条件クリアに対応する。

## 集計の意味

- 対象はDBに存在するプレイヤー。ランク・国・デバイスは**現在のプロフィール**を使い、対戦当時の情報ではない。
- 年齢は日本時間の当日を基準に、10歳未満、10代〜90代、100歳以上に分類する。
  生年月日が公開、または「非公開（統計利用を許可）」の人を含める。「秘密」・未登録は `unknown`。
  **統計利用許可だけでは個人ページに年齢を出さず、個人の年齢検索にも含めない。**
- ランク分布はDBの現在値（E / N / Ex / H / L / Ph）。初期設定のままのNなども含める。
- 個人ページのキャラ別勝率が**非公開の人も集団統計に含める**。個人ページ側の公開設定は変更しない。
- 勝敗または引き分けが確定した `matches` を集計する。未確定試合・未確定報告は除外し、リプレイや報告数では増えない。
- 対戦数は異なる試合IDの数。延べ対戦数はプレイヤー視点の参加数。同じ集団の2人の対戦なら前者は1、後者は2。
  相手が未同定でも、紐付いた本人側の戦績は含む。両側が同じアカウントIDならホスト側だけ数える。
- キャラ別の勝率＝勝利数÷延べ対戦数（引き分けを含む）。個人勝率の単純平均ではない。対戦がなければ勝率は `null`。
- 使用キャラはプロフィールのメインキャラではなく、その試合で記録されたID。
  20（ランダム）はDBに20として残る記録を指す。キャラが不明な試合はキャラ別行には含めない。
- 使用キャラや対戦種別を指定すると、該当戦績がある人だけがプロフィール分布の対象にもなる。
  どちらも未指定なら、対戦実績がない人もプロフィール分布に含む。

## 少人数の保護

- 最小人数は **5人**。対象者が0〜4人の場合は、対象人数・各分布・戦績をすべて非表示にする。
  0人と1〜4人は応答から区別できない。
- 分布中の1〜4人の区分は `count: null`。隠す区分が1つだけの場合は別の非ゼロ区分も伏せ、
  同じ表の「合計−表示値」だけでは正確な値が出ないようにする。補助的に伏せる区分は5人以上の場合もある。
- キャラ別戦績は、そのキャラを使った**異なるプレイヤー数**で判定する。
  1人が100試合していても非表示。隠す場合は対戦数・勝敗数・勝率をすべて `null` にする。
- キャラ別に非表示行がある場合、戦績のある人数・対戦数・延べ対戦数も伏せる。
  キャラ不明の戦績がある場合もこれらの合計は伏せ、差分からの復元を防ぐ。
- 名前・ID・生年月日・自由入力の検索条件は受け付けず、プレイヤー一覧も返さない。
  従来の全体統計APIにも同じ少人数ルールを適用する。
- この処理は単一の表からの直接的な逆算を抑えるもの。**複数の異なる検索や外部情報を合わせた推測まで防ぐ、
  数学的な匿名性の保証ではない。**

## API

`GET /api/players/analytics`。個人のCookieセッションまたは `Authorization: Bearer` で認証する。
応答は `Cache-Control: private, no-store`。未認証は401、不正・未知の条件は422。
異なる条件はAND。同じ項目に複数選択はなく、ランクのPhレートや勝率の数値検索は提供しない。

| クエリ | 値 | 既定値 |
| --- | --- | --- |
| `age_band` | `0` / `10` / `20` / … / `90` / `100` / `unknown`。0は10歳未満、100は100歳以上 | `""`（すべて） |
| `rank` | `easy` / `normal` / `ex` / `hard` / `luna` / `ph` | `""` |
| `country_code` | ISO alpha-2（小文字は大文字に変換）または `unknown` | `""` |
| `device_type` | `keyboard` / `gamepad` / `arcade` / `other` / `unknown` | `""` |
| `character` | 0〜20の整数（実際の使用キャラ） | 省略（すべて） |
| `match_type` | `all` / `ranked` / `casual` | `all` |

クエリの組み合わせ例（JSONはパラメーターの対応表で、GETの本文としては送らない）:

<!-- player-statistics-filters -->
```json
{
  "age_band": "20",
  "rank": "normal",
  "country_code": "JP",
  "device_type": "keyboard",
  "character": 0,
  "match_type": "ranked"
}
```

応答フィールド:

| フィールド | 型・意味 |
| --- | --- |
| `filters` | 正規化した条件。省略された値も上表の既定値（characterはnull）で返す |
| `as_of` | 日本時間の基準日 `YYYY-MM-DD` |
| `suppressed` | 集団全体を非表示にした場合true |
| `min_players` | 5 |
| `age_scope` / `match_scope` | `consented` / `all_confirmed` |
| `total_players` | 対象人数。全体非表示ならnull |
| `match_players` | 対象の確定戦績がある人数。保護が必要ならnull |
| `unique_matches` / `participations` | 対戦数 / 延べ対戦数。保護が必要ならnull |
| `unknown_character_games` | キャラ不明の延べ対戦数。保護により不明戦績があればnull（表示可能な場合は0） |
| `distributions` | `age_band` / `rank` / `country` / `device` をキーとする配列群。要素は `{key, count, suppressed}` |
| `characters` | 0〜20の順の `{char, games, wins, losses, draws, win_rate, suppressed}` 配列。勝率は0〜1、小数4桁 |

分布の `key` は年齢帯の文字列・内部ランク・国コード・デバイス種別。未登録や不明値は `unknown`。
国は該当する国＋unknown、その他の分布は0件の区分も返す。
全体非表示時は `distributions` の各配列と `characters` は空、全人数・戦績合計はnull。
行の `suppressed` がtrueの場合、その行の数値はnullであり、ゼロとは異なる。
年齢やキャラ別の個人一覧に遷移するURLは応答に含まない。

既存 `GET /api/players/statistics` は条件なしの同じ集計から国・年齢分布だけを返す。
返却形式は `{suppressed, min_players, countries:[{country_code,count}], age_bands:[{min,max,count}]}`。
少人数・補助抑制のcountはnull、全体非表示なら両配列は空。unknownは両配列から省く。

DBマイグレーション・クライアント更新は不要。サーバー更新で反映する。
検証: `test_player_statistics.py`、`player_statistics_ui.cjs`、既存プロフィール・ロビーの回帰テスト。
